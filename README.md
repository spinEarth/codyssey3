# Mini NPU Simulator

2차원 패턴(십자가, X)과 필터 간의 MAC(Multiply-Accumulate) 연산을 직접 구현하고, 데이터 크기 증가에 따른 연산량($N^2$)과 실행 시간 변화 및 부동소수점 비교 정책을 검증하는 Python 콘솔 시뮬레이터입니다.

## 1. 실행 방법

- **요구 환경**: Python 3.8 이상 (외부 라이브러리 미사용, 표준 라이브러리 `json`, `math`, `os`, `time`만 사용)
- **파일 위치**: `main.py`와 `data.json`이 같은 디렉터리에 위치해야 합니다(현재 작업 디렉터리 또는 `main.py`가 있는 디렉터리에서 `data.json` 자동 탐색).
- **실행 명령**:
  ```bash
  python3 main.py
  ```
- **모드 선택**:
  - `1`: 사용자 입력 (3×3) — 필터 A, B와 3×3 패턴을 공백 구분으로 입력받아 점수, 판정 결과, 3×3 평균 연산 시간을 확인합니다. (형식/행·열 개수 오류 시 재입력 유도)
  - `2`: `data.json` 분석 — `data.json`의 필터(`size_5`, `size_13`, `size_25`)와 6개 패턴을 일괄 검증·판정하고 성능 표 및 결과 요약을 출력합니다.
  - `3`: 보너스 — 크기 $N$을 입력받아 `Cross`/`X` 패턴을 자동 생성하고 2차원 접근 vs 1차원 평탄화 MAC 연산 속도를 비교합니다.

## 2. 구현 요약

- **자료구조 (`Matrix2D`)**: $N \times N$ 2차원 배열을 캡슐화하여 `get_value(row, col)`과 `set_value(row, col, value)`로 위치별 읽기/쓰기를 수행하고, 보너스 최적화용 `to_flat_list()`를 제공합니다.
- **라벨 정규화 (`normalize_label`)**: 필터 키(`'cross'`, `'x'`)와 패턴 기대값(`'+'`, `'x'`)을 내부 표준 라벨 `'Cross'`, `'X'`로 통일해 비교·출력 일관성을 보장합니다.
- **MAC 연산 (`compute_mac_2d`)**: 외부 라이브러리 없이 이중 `for` 반복문으로 각 좌표 $(r, c)$의 입력값과 필터 가중치를 곱한 뒤 누적 합산합니다.
- **동점 및 부동소수점 비교 정책 (`judge_scores`)**: `abs(score_a - score_b) < 1e-9`일 때 동점(`UNDECIDED` / `판정 불가`)으로 처리하여 IEEE 754 부동소수점 누적 오차로 인한 오판정을 방지합니다.
- **스키마/크기 검증**: `data.json` 분석 시 키 형식, 정사각 행렬 여부, 필터 존재 여부, 라벨 유효성을 케이스 단위로 검증하여 불일치가 발생해도 프로그램이 중단되지 않고 해당 케이스만 `FAIL`로 기록합니다.

## 3. 결과 리포트

### 3.1 `data.json` 실행 요약 및 실패(FAIL) 원인 분석

`python3 main.py`에서 모드 `2`를 실행한 결과 총 6개 테스트 중 **통과 3개(`size_5_2`, `size_13_1`, `size_25_2`), 실패 3개(`size_5_1`, `size_13_2`, `size_25_1`)**가 발생했습니다.

1. **로직/스키마 문제가 아닌 데이터 가중치 및 동점 규칙에 의한 FAIL**:
   - `size_5_1` (`expected: X`): 입력 패턴(`X` 모양)에 대해 `Cross` 필터는 중앙 `(2, 2)` 가중치 `0.9`만 곱해져 `0.9`가 되고, `X` 필터는 대각선 9개 위치의 `0.1`이 누적 합산되어 `0.8999999999999999`가 됩니다.
   - `size_13_2` (`expected: Cross`): 입력 패턴(`+` 모양)에 대해 `Cross` 필터는 가로·세로 25칸의 `0.3`이 누적 합산되어 `7.499999999999997`이 되고, `X` 필터는 중앙 `(6, 6)`에 집중된 가중치 `7.5`가 곱해져 `7.5`가 됩니다.
   - `size_25_1` (`expected: X`): 입력 패턴(`X` 모양)에 대해 `Cross` 필터는 중앙 `(12, 12)` 가중치 `4.9`가 적용되어 `4.9`가 되고, `X` 필터는 대각선 49칸의 `0.1`이 누적 합산되어 `4.899999999999999`가 됩니다.
2. **부동소수점 누적 오차와 `epsilon` 정책의 역할**:
   - IEEE 754 부동소수점 연산에서는 `0.1`을 9번 더한 `0.8999999999999999`와 `0.9`, `0.3`을 25번 더한 `7.499999999999997`과 `7.5`, `0.1`을 49번 더한 `4.899999999999999`와 `4.9`처럼 `1e-16`~`1e-15` 수준의 미세 오차가 실제로 발생합니다.
   - 만약 단순 `==` 또는 `>` 비교를 사용하면 `0.9 > 0.8999999999999999`, `7.5 > 7.499999999999997`, `4.9 > 4.899999999999999`로 판정되어 한쪽 필터가 우연히 승리하는 잘못된 PASS/FAIL이 발생합니다.
   - 허용오차 `1e-9` 기준을 적용함으로써 위 세 케이스를 일관되게 `UNDECIDED`로 판정하였고, 정답 라벨(`Cross` 또는 `X`)과 다르므로 정상적으로 `FAIL (동점(UNDECIDED) 처리 규칙에 따라 FAIL)`로 진단할 수 있었습니다.
   - 개선 관점에서는 현재 필터 가중치가 정답 패턴의 특이점(중앙 교차점)에 과도하게 집중되어 있으므로, 배경/비패턴 영역 구분력을 높이도록 필터 가중치 분포를 재설계해야 합니다.

### 3.2 성능 측정 및 시간 복잡도 $O(N^2)$ 분석

I/O 시간을 제외하고 `compute_mac_2d` 함수 호출 구간만 `time.perf_counter()`로 10회 반복 측정한 평균 결과는 다음과 같습니다.

| 크기 ($N \times N$) | 평균 시간 (ms) | 연산 횟수 ($N^2$) |
| --- | ---: | ---: |
| 3×3 | 0.0007 | 9 |
| 5×5 | 0.0017 | 25 |
| 13×13 | 0.0095 | 169 |
| 25×25 | 0.0329 | 625 |

- **시간 복잡도 근거**: `compute_mac_2d`는 행 인덱스 `0 ~ N-1`과 열 인덱스 `0 ~ N-1`을 순회하는 2중 반복문으로 구현되어 있으며, 매 반복에서 1회의 곱셈과 1회의 덧셈(MAC 1회)을 수행하므로 총 연산 횟수는 정확히 $N^2$에 비례합니다.
- **실측 결과 해석**: 입력 크기가 `5×5`(25회)에서 `13×13`(169회, 연산량 약 6.76배)으로 커질 때 평균 시간은 `0.0017 ms`에서 `0.0095 ms`(약 5.59배)로 증가했고, `25×25`(625회, `13×13` 대비 연산량 약 3.70배)에서는 `0.0329 ms`(약 3.46배)로 증가해 이론적 복잡도 $O(N^2)$와 일치하는 비례 추세를 보입니다.
- **보너스(1차원 평탄화 최적화) 비교**: 모드 `3`으로 25×25 행렬을 100회 반복 측정한 결과, 2차원 접근(`0.03138 ms`) 대비 1차원 평탄화 접근(`0.01076 ms`)이 약 2.9배 빠른 성능을 보였습니다. 이는 2중 루프 오버헤드와 메서드(`get_value`) 호출 비용이 단일 리스트 순회로 감소했기 때문입니다.

### 3.3 대규모 입력($1000 \times 1000$ 이상) 처리 한계 및 최적화 전략

현재 구현은 교육용 시뮬레이터로서 순수 Python 2중 리스트와 직렬 반복문을 사용하므로, $N \ge 1000$ 이상의 대규모 입력에서는 시간과 메모리 양쪽에서 명확한 한계가 발생합니다.

1. **시간 및 메모리 한계 (실측 및 구조 분석)**:
   - **시간 한계 ($O(N^2)$ 누적 비용)**: `1000×1000` 행렬($10^6$ 연산)을 직접 측정(3회 평균)한 결과, `compute_mac_2d`는 **`51.46 ms`**, `compute_mac_1d`는 **`19.15 ms`**가 소요되었습니다. 실제 AI 워크로드처럼 한 입력에 수천 개의 필터를 적용하면 순수 Python 직렬 처리만으로는 수십 초 이상 소요되어 실시간 처리가 불가능하며, $10{,}000 \times 10{,}000$($10^8$ 연산)에서는 단일 연산도 수 초대로 급증합니다.
   - **메모리 한계 (객체 박싱 및 비연속 배치)**: CPython에서 `1000×1000` `Matrix2D`의 2중 리스트 컨테이너 자체만 약 `7.69 MiB`를 차지하며, 각 원소마다 `24 bytes`의 `float` 객체가 별도 힙에 할당되어 행렬 1개당 약 `32 MB` 수준까지 증가합니다. $10{,}000 \times 10{,}000$ 이상에서는 행렬 1개당 수 GB를 소비하므로 메모리 부족(OOM) 위험이 커지고, 행별 리스트가 힙에 분산 배치되어 CPU 캐시 미스(Cache Miss)가 잦아집니다.
2. **대규모 N 처리를 위한 단계별 최적화 전략**:
   - **1단계 — 1차원 평탄화 및 연속 버퍼(Contiguous Buffer) 전환**: `to_flat_list()` 적용만으로 `1000×1000` 실행 시간이 `51.46 ms` → `19.15 ms`로 약 **2.69배** 단축되었습니다. 대규모 데이터에서는 `array.array`나 연속 바이트 버퍼를 사용해 포인터 간접 참조와 `float` 객체 박싱 오버헤드를 제거하는 것이 최우선입니다.
   - **2단계 — 블록(타일링, Tiling) 처리 및 지연 평가(Lazy Evaluation)**: 전체 $N \times N$ 행렬을 한꺼번에 메모리에 올리지 않고, 캐시 용량(L1/L2)에 맞는 블록(예: $64 \times 64$ 타일) 단위로 분할 처리하거나 제너레이터 기반의 지연 평가(필요 시점에만 행/블록을 읽어 부분합 누적)를 적용하면 피크 메모리 사용량을 $O(N^2)$에서 $O(B^2)$ 또는 $O(N)$으로 낮출 수 있습니다.
   - **3단계 — 벡터화(SIMD) 및 병렬화**: 인터프리터 루프를 C/어셈블리 수준 SIMD 벡터 명령(예: NumPy, AVX2/NEON)으로 대체하고, 독립적인 필터별·타일별 MAC 연산을 멀티스레드/멀티코어 또는 NPU/GPU 가속기로 분산 실행합니다.

### 3.4 CPU vs NPU 아키텍처 비교, 병목 분석 및 최적화 우선순위

1. **CPU vs NPU 실행 방식 비교**:
   - **CPU (직렬·범용 처리 중심)**: 소수의 고클럭 코어, 분기 예측기, 대용량 캐시 계층을 통해 복잡한 조건 분기와 순차 제어 흐름을 빠르게 처리합니다. 본 시뮬레이터의 `compute_mac_2d`처럼 루프 제어, 경계 검사, 누산기(accumulator) 순차 갱신을 한 줄씩 수행하는 구조는 전형적인 CPU 직렬 모델에 해당합니다.
   - **NPU (병렬 MAC 특화)**: 복잡한 분기 예측 회로를 줄이는 대신 수백~수천 개의 단순 MAC 연산기(예: Systolic Array)를 집적하여, 데이터 간 의존성이 없는 수많은 곱셈 연산을 한 클럭 사이클에 동시 처리합니다.
2. **핵심 병목 원인 분석 (연산 병렬성 vs 메모리 대역폭)**:
   - **연산 병렬성 병목 (Compute/Interpreter Bottleneck)**: 순수 Python 직렬 실행에서는 $N^2$개의 좌표 곱셈이 서로 독립적임에도 단일 스레드가 순차 처리하므로 연산 병렬성을 전혀 활용하지 못합니다.
   - **메모리 대역폭 병목 (Memory Wall)**: 단일 MAC 연산은 곱셈 1회·덧셈 1회(2 FLOPs)를 수행할 때마다 입력값과 가중치 2개를 읽어야 하므로 **산술 강도(Arithmetic Intensity)**가 매우 낮습니다(`float64` 16 bytes 기준 `0.125 FLOPs/byte`, `float32` 8 bytes 기준 `0.25 FLOPs/byte`). 따라서 연산기가 NPU처럼 병렬화될수록 DRAM 대역폭이 데이터를 제때 공급하지 못해 연산기가 대기하는 **메모리 대역폭 병목**이 지배적이 됩니다.
3. **병목에 기반한 최적화 우선순위**:
   1. **우선순위 1 — 메모리 접근 효율화 및 정밀도 경량화**: 1차원 연속 메모리 배치로 캐시 지역성을 확보하고, 허용오차 범위 내에서 `float64` → `float32`/`int8`(양자화)로 비트 폭을 줄여 메모리 대역폭 부담을 먼저 낮춥니다.
   2. **우선순위 2 — 데이터 재사용 극대화 (블록 연산 / 온칩 버퍼링)**: 입력 패턴을 온칩 캐시·SRAM에 유지한 채 다수 필터와 공유하거나 타일 단위로 재사용해 외부 메모리(DRAM) 왕복 횟수를 최소화합니다.
   3. **우선순위 3 — 연산 병렬화 및 벡터화**: 메모리 공급 병목을 완화한 뒤 SIMD 벡터화와 다중 필터 병렬 연산(NPU Systolic Array / 멀티코어 워커)을 적용해 전체 처리량(Throughput)을 극대화합니다.
